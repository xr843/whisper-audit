# 正确率可测量化、提升与开源化 —— 设计

日期：2026-08-05
状态：已实施。**本文是当时批准的设计快照，不再回填。**

> ⚠️ 实施过程中有三处结论被实测推翻，本文保留原样以存档，**以
> [docs/measurements.md](../../measurements.md) 为准**：
>
> 1. **拼音纠错默认方向反了**。本文写的是默认开、`--no-pinyin-fix` 关；
>    实际是**默认关**、`--pinyin-fix` 开。原因：无调拼音会把两个真实存在、
>    含义不同的词判成同一个（节余/结余、空值/控制），补术语堵不住。
> 2. **`旧港→旧账` 不是同音字对**。港 gang / 账 zhang，声母都不同，
>    连近音都合不到一起。本文多处拿它论证同音校订的价值，那个论证不成立。
> 3. **速度数字 8.8x / 8.4x 是错的**。当时 GPU 上有别的负载，
>    空闲 GPU 上复测约 24.5x，词级时间戳代价是个位数百分比而非精确的 5%。

## 背景

流水线已经能跑通，也有一套围绕「不遗漏」的审计机制。但它**从未测过正确率**。
所有质量话术都是覆盖率——转到了多少；没有任何数字回答转对了多少。

覆盖率 100% 的稿子可以句句是错的。实测成品里这类错不是边角料：

```
旧港倒进去镜杆倒进去倒到心脏里面去   实际是「旧账导进去、明细账导进去、导到新账里面去」
垦墓而葬 / 垦墓级别                  固定资产科目相关
文物之源                             无形资产
```

没有尺子的代价已经付过一次：README 里「细粒度那一路多出 5,004 字」的招牌数字虚高约 2.8 倍，
因为旧算法把一条 segment 在它跨过的每个窗口都整段计数。按时间重叠比例摊回后净贡献只有 1,792 字。

## 目标

1. **正确率可测量、可保证** —— 建立字级 CER 评测与回归门禁
2. **速度不退化** —— 默认档保持现有速度，高精度另开一档
3. **可开源** —— 能作为独立项目放到 GitHub，别人 clone 下来能跑、能验证

## 非目标

- 说话人分离（另一件事，不在本轮）
- 领域微调 / 训练（本轮只做推理侧）
- 把 README 全文英译（价值在中文实测记录，只加英文摘要）

### Engine 接口

```python
class Engine:
    name: str
    def transcribe(self, wav: str, **opts) -> dict:
        """返回 {"duration": float, "segments": [
             {"start","end","text","avg_logprob","no_speech_prob","words":[...]}]}"""
```

`words` 允许为空列表——FunASR 的时间戳粒度与格式不同，缺失时下游自动降级
（字幕退回整段、段内标点不加），不阻塞主流程。

## A. 评测体系

### A1. 指标

规范化后做**字级编辑距离**，拆成三类。规范化包括：繁→简（opencc）、去标点、
全角转半角、去空白。数字统一为阿拉伯数字。

报告四个数，其中后两个是本项目专属：

- **CER** —— 总错误率，(S+D+I)/N
- **替换率 S** / **插入率 I**
- **删除率 D** —— 「不遗漏」这个卖点的直接度量。过去只有覆盖率在代理它
- **同音替换率** —— S 里拼音相同的占比。这个数直接给出拼音纠错与 LLM 校订的天花板，
  是后续所有取舍的依据

实现用 `rapidfuzz`（MIT，C++ 后端）取 opcodes 做 S/D/I 分解。
纯 Python DP 在 5,000 字量级要 ~30 秒，评测会被跑测试的人绕开，不可接受。

### A2. 金标

格式 `*.gold.tsv`，两列：

```
00:12:34<TAB>这里是这一条的正确文本
```

由 `goldset.py` 从跑完的输出目录直接生成（默认取 ASR 结果作为初稿）。
**人工只改错字，不碰格式、不打时间戳、不做对齐。**

两层数据：

| 层 | 内容 | 进仓库 | 作用 |
|---|---|---|---|
| CI 夹具 | 小、确定性 | 是 | 防回归，别人 clone 下来能跑 |
| 真实基准 | 自建 10~15 分钟 + AISHELL-1 test | 否 | 报绝对 CER |

评测工具 **manifest 驱动**（`{audio, text}` 的 jsonl），公开集因网络下不动时不阻塞任何事。

### A3. 命令

```bash
audio-transcribe goldset 输出目录/ --from 00:10:00 --to 00:25:00 -o sample.gold.tsv
audio-transcribe eval --gold sample.gold.tsv --hyp 输出目录/
```

输出表格到终端，同时写 `eval_report.json` 供门禁比对。

## B. 提升手段

三条路各自可开关、各报独立 CER 增量。

### B1. 拼音级术语纠错（零速度成本）

现在的术语表是字面替换，54 条里 12 条从未命中——因为误识写法穷举不完。

改为：术语表新增 `terms` 字段（只列**正确写法**），滑窗扫描正文，
对候选 n-gram 算拼音，与正确写法的拼音比对，**只在拼音一致或极近时替换**。
一条规则覆盖一整类同音错。依赖 `pypinyin`（MIT）。

护栏：
- 所有改动记账写入质检报告（位置、原文、替换后、拼音）
- `--no-pinyin-fix` 可关
- 单测锁死：拼音不同的词一律不许改动

`fixes`（精确字面替换）保留，优先级高于拼音匹配。

### B2. 中文专用 ASR 第二路

引入 FunASR（Paraformer / SenseVoice），替代现在「同模型不同 chunk」的第二路。
理由：跨模型互补性远大于同模型——现在双路净贡献只有 1,792 字（4%），却要付 +31 分钟。

Paraformer 是非自回归模型，速度快，预期不会拖慢默认档。

合并逻辑复用现有 `combine`（30 秒窗口取字多者 + `strip_common` 文本级并集）。
跨引擎时分段差异更大，这个策略是否仍然合适**由 CER 裁决**，不预设结论。

### B3. LLM 校订（高精度档专用）

`--polish` 开启，默认关闭。OpenAI 兼容 endpoint（`--llm-base-url` / `--llm-model`，
key 走环境变量）。分块发送全文。

**关键护栏：返回后逐字校验拼音，拼音不一致的改动一律拒绝并记账。**

这把 LLM 自由发挥、删内容、改事实的风险堵在门外——它只被允许做同音替换，
也就是只修 `旧港→旧账` 这类错。这个约束是可测的，有单测锁死。

术语纠错在 LLM **前后各跑一次**：前一次给 LLM 干净输入，后一次兜底覆盖 LLM 的任何反悔。
代价接近零。

数据外发的边界已与项目所有者确认：文本即内容，与音频承载同一份信息；
所有者判断该内容可以出本机。此档默认关闭，需显式开启。

## 档位与速度预算

| 档位 | 组成 | 速度 |
|---|---|---|
| `lecture` | 单路 whisper + 审计 + 补转 + 拼音纠错 | 不退化 |
| `meeting` | 双引擎 + 审计 + 补转 + 拼音纠错 | 不退化 |
| `accurate` | 双引擎 + 补转 + 拼音纠错 + LLM 校订 | 不限 |

**硬要求：默认档（lecture / meeting）速度退化不得超过 5%。**

基线必须可复现，所以固定一段基准音频测吞吐，而不是拿「上次那份录音跑了多久」当基线
（那份录音的源音频已丢失，无法复跑）。基准：15 分钟片段、`int8_float16`、batch 16、beam 5，
已测得 **8.8x 实时**（word_timestamps 关）/ **8.4x 实时**（开）。
基准片段与测量脚本进仓库，`bench/throughput.py`。

## 验证纪律

这个项目已经栽过两次「静悄悄改内容」：休息段边界吞掉整句「接下来我们开始互动的环节」，
法规名过长导致后半句真话被判为重复删除。所以：

1. 拼音纠错与 LLM 校订**必须**有「不许改动拼音不同的字」的锁死测试
2. **每项提升都要拿出独立的 CER 增量数字**，测不出收益的默认关掉，而不是「装上了就开着」
3. 任何「自动删掉内容」的逻辑都要有测试盯住被删区间的边界

## 已知风险

| 风险 | 应对 |
|---|---|
| 本机走代理，AISHELL-1 下载可能失败 | 评测 manifest 驱动，公开集缺失不阻塞；CI 夹具独立 |
| FunASR 模型下载同上 | 引擎可选，缺失时自动退回单引擎并告警 |
| 归档那份讲座的源音频已丢失 | 真实金标只能用新录音或现有其他音频；那份 3.65 小时稿的 CER 无法回溯测量 |
| 跨引擎合并策略可能不适用 | 由 CER 裁决，不预设；不合格就退回同引擎双路 |
| 8GB 显存跑双引擎 | 引擎分时加载，不同时驻留 |
